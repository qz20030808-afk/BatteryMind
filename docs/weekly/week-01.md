# Week 01：CSV 输入检查器

## 1. 本周面对的真实问题

电池实验数据进入分析、SOH 模型或 Agent 之前，可能出现路径不存在、把目录当文件、后缀错误、空文件、没有数据行和核心字段缺失等问题。如果一直到上层流程才失败，错误会更难定位。

因此，本周先完成一个确定性的 CSV 输入检查器，把非法输入挡在数据入口，并用自动测试保存行为证据。

## 2. 我完成的行动链

```text
CSV 路径
  → Path 检查存在性、文件类型、后缀和大小
  → Pandas 读取 DataFrame
  → 检查 battery_id、cycle、capacity
  → 返回检查结果
  → pytest 重放正常与异常场景
```

另外，我通过独立练习程序理解了命令行参数、JSON 结构化输出和退出码，但它们目前还没有正式整合进主脚本。

## 3. 关键设计选择

### 为什么先做确定性工具，而不是直接做 Agent

Agent 的上层判断依赖稳定工具与可信输入。先把路径检查、数据读取和字段契约做成可测试函数，后续才能区分数据工具错误、检索错误和 Agent 决策错误。

### 为什么把逻辑拆成小函数

`validate_input_path`、`load_csv` 和 `find_missing_columns` 分别负责路径、读取和字段检查。职责分开后，可以单独测试每种失败，也方便后续组合成 CLI 或 Agent tool。

### 为什么加入 pytest

手动运行正常样例只能证明一次成功。pytest 会自动重放正常文件、缺列、缺文件、错后缀、空文件、目录输入以及两条 CLI 行为检查，防止后续修改破坏旧能力。

## 4. 本周遇到并理解的故障

- Git 安装后旧 PowerShell 会话仍找不到命令，需要重新打开终端并确认 `git --version`；
- VS Code 的运行按钮曾选择 `D:\Python\python.exe`，与 Conda 的 `batterymind` 解释器不是同一个环境；
- 测试文件应该由 `python -m pytest` 收集，不能当普通 Python 脚本直接运行；
- 直接运行文件与从项目根目录运行模块时，Python 的导入搜索起点不同，需要让命令与 import 写法一致。

这些故障让我形成了先检查当前目录、`sys.executable`、启动方式和完整错误信息，再判断是否缺依赖的排错顺序。

## 6. 当前限制

- 主脚本仍使用固定样例路径，还没有接收任意 CLI 输入；
- JSON 和退出码尚未整合进主脚本；
- 还没有处理缺失值、重复值、异常值和电池时序一致性；
- 尚未实现 SOH、RAG、Agent 编排和端到端评测；
- 当前数据规模很小，没有大文件性能证据。
